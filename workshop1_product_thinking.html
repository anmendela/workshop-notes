02

Проблема: погана специфікація

Спеку згенерував CTO за допомогою ChatGPT — дуже швиденько. Прийшов із нею до нас. Далі почався хаос.
Погана спека — ознаки
  • Один великий блок нечитабельного тексту
  • Відсутній Screen Flow (послідовність скринів)
  • Поп-апи "з нізвідки", без прив'язки до флоу
  • Немає описів станів кнопок
  • Немає референсів та прикладів
  • Нечіткі acceptance criteria
  • Відсутній Blank State для пустих екранів
Гарна спека — ознаки
  • Структурована, з чіткими блоками та заголовками
  • Є Screen Flow з логічним зв'язком екранів
  • Детальний опис кожного стану UI
  • Описані edge-кейси та сценарії
  • Є готові copy-тексти для інтерфейсу
  • Лінки на референсні скрини
  • Виділені відкриті питання (open questions)
💡

Наслідок поганої спеки: дизайнер-джун отримує її, не розуміє очікувань і малює "в сліпу". Результат — неузгоджені екрани, втрачені дні, "прожигання" бюджету клієнта.

🛠 Що менеджер міг зробити по-іншому ▼
  • Зробити додаткову сесію з клієнтом (Discovery) перед передачею дизайнеру
  • Скласти чіткий Screen Flow зі всіма попапами та переходами
  • Надати референси та прототип для орієнтації
  • Прописати Definition of Done та Acceptance Criteria
  • Обов'язковий онбординг дизайнера на продукт як користувача
  • Залучити сеньор-дизайнера хоча б на першій сесії
  • Налаштувати м'який feedback-процес з урахуванням культури (The Culture Map)
  • Завжди починати фідбек із похвали позитивного
  • Записувати дзвінки та фіксувати рішення в документах
03

Screen Flow як рятівник

Що таке Screen Flow

Послідовна схема скринів із зазначенням дій на кожному екрані. Показує логічний зв'язок між усіма екранами, попапами та станами інтерфейсу. Заповнює прогалини специфікації там, де тексту недостатньо.

⚡

Дизайнери часто не тестують продукт. Без Screen Flow вони працюють наосліп і пропускають критичні стани. Blank State (порожній вигляд сторінки) — типовий приклад того, що забувають.

📋 Приклад вправи: що додати у Screen Flow ▼

Учасниці аналізували флоу зміни плану та управління активами. Типові "загублені" скрини:

  • Модальне вікно вибору кількості кредитів (Refill Credits)
  • Confirmation / Rejected стан після додавання платіжного методу
  • Порожній стан сторінки інвойсів (Blank State)
  • Filter by Text / Audio / Video у "My Assets"
  • Multi-select дії для кількох активів
  • Add Billing Method as Default / Delete Billing Method
Правило: якщо є чекбокси → мають бути показані дії над обраними елементами (bulk actions).
04

Анатомія гарної специфікації

Структура

Розбита на логічні секції. Легко читається. Таблиці — де доречно. Використовуються заголовки, не суцільний текст.

Деталізація UI

Описано всі стани кнопок, copy-тексти на екранах, формати файлів, edge-кейси, Blank States.

Зрозумілість

Спека для всієї команди — дизайнер, розробник, тестувальник, клієнт. Не окремо для кожного.

Open Questions

Виділено окремо питання, які ще відкриті. Читач одразу бачить, що ще не вирішено.

📌

Bus Factor: вся ключова інформація має жити в документах, а не в голові 1–2 людей. Якщо Bus Factor = 1, проект у зоні ризику.

📖 Definition of Done vs Definition of Ready vs Acceptance Criteria ▼
Acceptance Criteria
Чіткі умови, за яких конкретна user story вважається виконаною. Відрізняються для кожної задачі. Основний інструмент узгодження очікувань.
Definition of Done
Організаційні критерії завершення задачі: закриті баги, проведено smoke-testing, задеплоєно на прод. Однакові для всіх user stories проекту.
Definition of Ready
Критерії готовності user story до взяття в розробку: проведено Discovery, додані макапи, описані всі стани. Перевіряється на Refinement.
05

Mermaid User Flow + AI

Що таке Mermaid

Текстовий формат для створення діаграм: ти пишеш (або генеруєш) код — він автоматично стає красивою схемою. FigJam автоматично конвертує Mermaid-код у візуальну діаграму через Ctrl+V.

🤖 Як генерувати User Flow через AI ▼

Спосіб 1 — через ChatGPT / Claude:

  1. Завантажити PDF/документ зі специфікацією
  2. Використати промт (нижче)
  3. Отримати Mermaid-код або одразу діаграму
  4. Скопіювати код → відкрити FigJam → Ctrl+V → діаграма готова
  5. Всі елементи стають редагованими у FigJam
Розробники просто цілувати вас будуть за цей юзерфлоу — він допомагає зрозуміти специфікацію.
Generate a Mermaid flowchart for the user flow based on the attached specification document.

Include all screens, modals, transitions, and edge cases.
Format as valid Mermaid syntax only, no explanations.
⚠️

AI не завжди дає ідеальний результат. Завжди перечитуй — людина має контролювати вихідний матеріал. Сліпо не довіряй навіть гарному результату.

06

AI-інструменти та практичні поради

Claude

Найкраще підходить для написання специфікацій. Працює як BA: пропонує питання, які можуть поставити розробники, обґрунтовує рішення через assumptions.

Специфікації HTML-файли Claude Code
ChatGPT

Добре генерує Mermaid-діаграми. Платна версія одразу видає готову діаграму без проміжного коду.

Mermaid User Flow
🏗 Як клієнту показати прототип без дизайнера ▼
  • Підготувати нормальну специфікацію
  • Зібрати брендбук клієнта: кольори, шрифти, лого
  • Завантажити шрифти прямо в Claude
  • Попросити Claude: "Зроби HTML-файл за цією специфікацією в стилі брендбука"
  • Або використати Claude Code / Cowork для збереження файлів локально
  • В Claude можна перемикати розміри девайсів прямо у вбудованому переглядачі
Це не замінює роботу дизайнера — це інструмент погодження для клієнта, щоб proof of concept відбувся ДО розробки.
📝 Промт для покращення специфікації ▼
You are a senior Product Manager. Review the attached specification and:
1. Restructure it with clear sections and headers
2. Add missing details: button states, copy texts, edge cases, blank states
3. Highlight open questions that need team discussion
4. Make it readable for the entire team: designer, developer, QA, client

Return the full improved specification in Markdown format.

Додатково можна запитати: "Які питання можуть поставити розробники по цій специфікації? Запропонуй відповіді та поділись assumptions, які ти враховував."

07

Ключові терміни

Screen Flow
Послідовна схема всіх скринів із логічними переходами та попапами. Обов'язковий елемент передачі задачі дизайнеру.
Blank State
Порожній вигляд сторінки/блоку, коли немає контенту. Дизайнери часто забувають його показати.
Bus Factor
Кількість людей-носіїв критичної інформації. Має бути >1. Якщо = 1 — проект у зоні ризику.
Mermaid
Текстовий синтаксис для автоматичного генерування діаграм. Підтримується у FigJam, Notion, GitHub.
Lean Methodology
Фреймворк для малих самоорганізованих команд, що свідомо прибирає зайві зустрічі та процеси.
The Culture Map
Книга Ерін Мейер про різницю ділових культур. Допомагає давати м'який фідбек міжнародним командам.
